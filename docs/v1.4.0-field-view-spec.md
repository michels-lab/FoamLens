# FoamLens v1.4.0 Field View — development specification

Date: 2026-09-29  
Branch: `development/v1.4.0-field-view`  
Base: FoamLens Desktop v1.3.2 / frontend v51

## Goal

Add an interactive OpenFOAM field visualizer to FoamLens so transient solved fields can be inspected directly on the case mesh instead of only through plots and reductions.

## Implemented in the first v1.4 vertical slice

- New **Field View** data tab, isolated in `v14-field-view.js`.
- Generic extension loading (`v*-*.js`) so v1.4 functionality does not require rewriting the existing v51 monolithic frontend.
- OpenFOAM `constant/polyMesh` discovery for the default region and named multi-regions.
- Native read-only Desktop parser for ASCII `points`, `faces`, `owner`, and `neighbour`.
- JavaScript ASCII fallback parser for non-native execution/tests.
- Boundary-surface triangulation and unique surface-edge extraction.
- Cell-centre approximation from surrounding face centres for field/vector visualization.
- WebGL 3D renderer with orbit camera, wheel zoom, reset camera, surface opacity, mesh edges, and responsive resizing.
- Cell-centred scalar coloring on the boundary surface using the real OpenFOAM field values.
- Scalar and vector components, including vector magnitude.
- Physical-time playback using the native field inventory and the existing FoamLens field cache/parser.
- Previous/next controls and 0.25× / 0.5× / 1× / 2× / 4× playback.
- Viridis, Turbo, and cool–warm color maps.
- Optional locked color range so a time animation can be compared without the legend rescaling every frame.
- Vector glyphs rendered from the selected cell-centred vector field; glyph direction follows the vector and glyph length/color reflects magnitude.
- Streamlines seeded from a configurable X/Y/Z plane.
- Streamlines use the actual instantaneous cell-centred vector field and a local inverse-distance interpolation with midpoint (RK2-style) integration.
- Multi-region eligibility: a case is visualizable when any region has both a complete mesh and compatible volume scalar/vector fields.
- Reconstructed-case safety: a decomposed field is not silently mapped onto a reconstructed mesh; FoamLens asks for reconstruction when the field/mesh topology cannot be matched.

## Current limitations kept explicit

- Mesh format: Desktop-native Field View supports ASCII and OpenFOAM binary `polyMesh` (including `faceCompactList`, 32/64-bit labels/scalars and LSB/MSB when declared by `arch`). The browser/JavaScript fallback remains ASCII-only.
- Mesh source: this first slice uses `constant/polyMesh`; moving/dynamic meshes written at later times are not yet animated.
- Field association: first slice targets volume scalar/vector fields. Surface/point fields are not yet mapped onto the renderer.
- Streamline interpolation is cell-centred and approximate. It is derived from real `U` values but is not intended to numerically duplicate ParaView/VTK interpolation bit-for-bit.
- QuickCup real-regression repository validates real OpenFOAM fields/postProcessing but does **not** contain `polyMesh` files, so mesh rendering is currently validated with a synthetic OpenFOAM cube fixture plus Windows packaging/smoke tests.
- The QuickCup cases use `writeFormat ascii`, which matches the implemented mesh path.

## Next Field View milestones

1. **Slices / clipping planes** — inspect internal T, p, alpha, |U|, etc. instead of only the exterior surface.
2. **Iso-surfaces / contours** — e.g. `alphaL = 0.5` or a selected isotherm.
3. **Cell picking / probe** — click a rendered location and inspect cell ID, coordinates, field values, and value-vs-time.
4. **Synchronized case comparison** — two cameras/time clocks locked together.
5. **Difference field view** — for compatible meshes, render A−B directly on the mesh.
6. **Dynamic mesh** support when the topology/points change with time.

## Validation

The dedicated `desktop/tests/field-view.test.cjs` suite checks:

- valid OpenFOAM cube mesh parsing;
- surface triangulation and edge counts;
- default/named-region mesh inventory;
- multi-region Field View availability;
- irregular physical-time navigation;
- finite normalized colormaps;
- streamline integration on a known uniform velocity field;
- native Desktop bridge wiring;
- WebGL/field/vector/streamline product wiring;
- generic versioned frontend extension loading.

The normal FoamLens workflow also continues to run the existing scientific, UI, QuickCup, portable executable, installer, and installed-app smoke suites.
