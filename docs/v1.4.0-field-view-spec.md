# FoamLens v1.4.x Field View — current implementation specification

Date updated: 2026-09-30  
Candidate branch: `fix/v1.4.1-field-view-discovery`  
Current public release: FoamLens Desktop v1.4.0 / frontend v51  
Candidate build: FoamLens Desktop v1.4.1 / frontend v51

## Goal

Provide an interactive OpenFOAM field visualizer inside FoamLens so transient solved fields can be inspected directly on the case mesh, synchronized in physical time, without requiring ParaView for routine thesis diagnostics.

## Implemented in the v1.4.1 candidate

### Mesh discovery and parsing
- Default-region and named multi-region `polyMesh` discovery.
- Desktop-native read-only parser for ASCII and OpenFOAM binary:
  - `points`;
  - `faces` / `faceCompactList`;
  - `owner`;
  - `neighbour`.
- Binary parser reads declared `arch` endianness plus 32/64-bit labels/scalars and rejects unsupported layouts explicitly.
- JavaScript/browser fallback remains ASCII-only.
- Full face-point/owner/neighbour connectivity is retained for volumetric reconstruction.
- Cell centres use volume-weighted polyhedral centroids, with an explicit mean-face fallback only for degenerate cells.
- Time-varying mesh discovery supports `<time>/[region/]polyMesh`.
- Moving-mesh `points` may inherit the latest valid topology.
- Topology-changing snapshots replace previous topology from their physical time onward.
- Mesh resolution is causal: `t_mesh <= t_field`; future geometry is never borrowed.

### 3D rendering and physical-time playback
- WebGL renderer with orbit camera, wheel zoom and reset camera.
- Boundary surface, mesh edges and configurable opacity.
- Association-aware scalar coloring and vector magnitude/components:
  - `vol*Field` → cell-centred values, with boundary triangles colored from their exact owner cells;
  - `point*Field` → direct point values on the actual mesh vertices;
  - `surface*Field` → `internalField` values on the actual internal mesh faces.
- Field selector labels the association explicitly as Cell / Face / Point.
- `surface*Field` rendering preserves both `internalField` values on internal faces and explicit `boundaryField` values on the exact boundary faces defined by `polyMesh/boundary`; patches without explicit numeric values remain neutral/unavailable.
- Physical-time slider, previous/next and 0.25× / 0.5× / 1× / 2× / 4× playback.
- Locked/unlocked color ranges and Viridis/Turbo/cool–warm maps.
- Dynamic mesh geometry updates during playback while preserving the user's camera.

### Interior visualization
- Real interior slices reconstructed from the polyhedral mesh.
- Cell-centred values are reconstructed to mesh points by adjacent-cell inverse-distance interpolation.
- Polyhedral cells are decomposed into tetrahedra for plane intersection.
- X/Y/Z slice plane, normalized position and opacity controls.
- 3D iso-surfaces / contours via marching tetrahedra.
- Explicit iso value, opacity and current-midrange helper.
- Typical solidification use: `alphaL = 0.5` as a mid-front contour or an explicitly selected isotherm.

### Vectors and streamlines
- Vector glyphs use the instantaneous selected cell-centred vector field.
- Streamlines use local inverse-distance vector interpolation and midpoint/RK2-style integration.
- Seed plane X/Y/Z, position and configurable seed count.
- Streamlines/glyphs update with physical-time playback and dynamic mesh state.

### 3D probe / picking
- True ray/triangle picking against boundary surfaces, slices and iso-surfaces.
- Reports selected field/value, physical time, coordinates and cell/nearest-cell identity where available.
- Volume-field boundary picks resolve the exact owner cell.
- Point-field boundary picks use barycentric interpolation of the actual triangle-vertex point values.
- Surface-field picks resolve the exact internal face and its `internalField` value.
- Slice values use barycentric interpolation.
- Iso picks report the explicit constant iso value.
- Probe markers are cleared when field/time/mesh state changes so stale values are not shown.

### Case comparison and differences
- Synchronized side-by-side 3D case comparison.
- Shared physical-time resolution.
- Optional signed difference viewport: `Δ = Primary − Comparison`.
- Difference view requires strict mesh equivalence:
  - point/face/cell counts;
  - point coordinates within tolerance;
  - face offsets/connectivity;
  - owner/neighbour labels.
- FoamLens refuses to subtract incompatible meshes instead of silently matching cell indices.

## Current explicit limitations

- **Interior reconstruction association:** Interior Slice and Iso-surface currently require a cell-centred `vol*Field`. Face- and point-associated fields are not silently coerced to cells.
- **Browser fallback:** binary `polyMesh` is a Desktop-native capability; browser fallback is ASCII-only.
- **Streamline equivalence:** FoamLens streamlines are derived from real field values but the interpolation/integration is not claimed to be bit-identical to ParaView/VTK.
- **Interior reconstruction equivalence:** slices and iso-surfaces use documented FoamLens reconstruction/tetrahedralization and are not claimed to be bit-identical to ParaView/VTK.
- **Real thesis mesh regression:** the QuickCup regression repository contains real fields/postProcessing but does not currently version its `polyMesh`; therefore actual QuickCup mesh rendering cannot be CI-regressed from that repository. Generic geometry is covered by analytic/synthetic OpenFOAM mesh fixtures and Windows executable smoke tests.
- **Decomposed fields:** processor-partitioned fields are not silently mapped onto a reconstructed mesh. Reconstruct the case before 3D visualization when a unique topology/value correspondence is unavailable.

## Validation coverage

Dedicated regressions now cover:
- ASCII cube and asymmetric-polyhedron mesh parsing;
- native binary `polyMesh` self-test in portable and installed executables;
- volume-weighted polyhedral centroids;
- named/default multi-region mesh discovery;
- time-varying/dynamic mesh snapshot inheritance and topology changes;
- physical-time mesh selection with no future-geometry leakage;
- cell-/internal-face-/point-associated scalar/vector/component rendering;
- explicit surface-field boundary-patch mapping;
- colormaps and locked ranges;
- vector glyphs and streamlines;
- interior slices;
- iso-surfaces;
- 3D probe picking;
- synchronized comparison and strict 3D difference fields;
- compatibility with legacy static v1.4.0 mesh inventories.

The normal FoamLens workflow additionally runs all scientific/UI regressions, the real QuickCup integration fixture, portable EXE smoke, installer build, installed-app smoke and artifact upload.
